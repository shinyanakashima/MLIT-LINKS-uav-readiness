# 防災・災害対応ドローン即応リソースマップ

災害時に動けるドローン（夜間・目視外に対応した「災害対応」運用）が、**全国のどの地域にどれだけいそうか**を地図で見られる Web アプリです。国土交通省のオープンデータをもとに、市区町村ごとの「即応度」を推定して可視化します。

🗺 **公開サイト**: https://shinyanakashima.github.io/MLIT-LINKS-uav-readiness/

> ⚠️ **はじめにお読みください**
> このマップは、ドローンの飛行「**計画（申請）**」データをもとにした**推定**です。実際に災害時へ出動できる体制や、各事業者の実力を保証するものではありません。また元データは紙資料のスキャンから抽出されたもので、完全性・正確性は保証されていません。**目安・初期スクリーニング用**としてご利用ください。

---

## 何のためのもの？

自治体の防災担当や、災害時応援協定を企画する方が、

- 「自分の地域に、夜間や目視外でも飛ばせる災害対応ドローンの運用がどれくらいあるか」
- 「近隣のどこに、そうした運用が厚く分布しているか」

を、ひと目で把握するための**たたき台**として作っています。協定先の検討や、ヒアリング対象の絞り込みといった「最初の見当をつける」用途を想定しています。

---

## 地図の見方

- 地図上の**円は市区町村**を表します（円の位置はその市区町村のおおよその中心）。
- **円が大きく・色が濃い**ほど、選択中の指標の値が高い地域です。
- **円をクリック**すると、その市区町村の内訳（災害対応の計画数・夜間・目視外・両対応の数、よく使われる機体の種類）が表示されます。
- 左側のパネルで**指標の切り替え**・**絞り込み**・**ランキング**が操作できます。
- 右上の **日本語 / English** ボタンで表示言語を切り替えられます（地名・機体名はデータの正式名称のため日本語のまま表示します）。

### 切り替えられる指標

| 指標 | 意味 |
|---|---|
| 即応度スコア | 災害対応の計画を「能力の高さ」で重み付けして合計した総合指標（下記の式参照）。既定の表示。 |
| 完全対応（夜間×目視外） | 夜間にも目視外にも対応できる災害対応計画の数。停電下や広域捜索など、災害時に最も役立つ運用の目安。 |
| 夜間対応 | 夜間飛行に対応した災害対応計画の数。 |
| 目視外対応 | 目視外（遠隔・長距離）飛行に対応した災害対応計画の数。 |
| 災害対応 計画数 | 飛行目的に「事故・災害対応等」を含む計画の数。 |

### 絞り込み（能力フィルタ）

夜間対応あり／目視外対応あり／完全対応あり、都道府県、機体の種類、北海道・十勝管内のみ —— で表示を絞れます。

## 数字を読むときの注意

- **「計画（申請）」の件数であって、ドローンの台数や事業者数ではありません。** 同じ事業者が毎日のように飛行計画を出していれば、その地域の件数は大きくなります。件数の多寡は「申請活動の活発さ」を表すとお考えください。
- 大都市や、大規模に運用する事業者がいる地域に件数が偏ります。**ランキング上位＝災害に強い、と単純には言えません。** 「完全対応」の比率なども併せてご覧ください。
- あくまで**推定**です。実態は一次情報（事業者への確認、協定内容など）でご確認ください。

## 用語

- **目視外（BVLOS）**: 操縦者がドローンを直接目で見ずに飛行させること。広域・長距離の捜索や被害把握に必要。
- **夜間飛行**: 日没後の飛行。停電時や夜間の捜索に必要。
- **即応度スコア**: 本アプリ独自の指標。各市区町村について、災害対応計画を能力で重み付けして合算します。

  ```
  スコア = 3 × 完全対応（夜間かつ目視外）
        + 2 × （夜間のみ ＋ 目視外のみ）
        + 1 × （夜間・目視外いずれも無し）
  ```

## 開発者向け情報

素の HTML / CSS / JavaScript と [Leaflet](https://leafletjs.com/) のみで動く静的サイトです。ビルド工程はありません。地図の下地は OpenStreetMap タイルを使い、API キーは不要です。公開済みデータ `data/processed/readiness.json`（約600KB）だけを配信し、生データ（合計約8.7GB）は配信しません。

### ディレクトリ構成

```
index.html                  画面本体
assets/app.js               地図描画・フィルタ・日英切替のロジック
assets/style.css            スタイル
vendor/leaflet/             Leaflet 1.9.4（同梱）
data/processed/readiness.json  集計済みデータ（配信対象）
data/raw/                   生 GeoJSON（.gitignore・配信しない）
scripts/download.sh         生データ取得スクリプト
scripts/process.py          集計スクリプト
scripts/files.txt           取得対象（リソースID×ファイル名）
.github/workflows/deploy-pages.yml  GitHub Pages 自動デプロイ
```

### データを更新する手順

```bash
# 1. 生データを取得（月次 GeoJSON 16ファイル / 合計 約8.7GB を data/raw/ へ）
bash scripts/download.sh

# 2. 集計して data/processed/readiness.json を再生成
pip install ijson
python3 scripts/process.py

# 3. コミットして main に push すると GitHub Actions が自動でデプロイ
git add data/processed/readiness.json && git commit -m "データ更新" && git push origin main
```

巨大ファイルのため、`process.py` は `ijson` でストリーミング処理し、各 Feature の `properties` のみを走査します（飛行範囲の Polygon ジオメトリは読み込みません）。`readiness.json` は市区町村単位の集計に要約され、座標は出発地の重心点のみを保持します。

### 元データの「癖」と前処理方針

実データには以下の問題があり、`process.py` で対処しています。

- **フィールド名の表記ゆれ**: 末尾スペースや異体字（例: `機体認証(⼀種)` に部首字が混入）。読込時に NFKC 正規化＋`strip()` で吸収してから参照します。
- **包括申請ノイズ**: 飛行目的フラグが多数立つ「とりあえず全項目チェック」とみられる行が混在。災害対応フラグ付き行のフラグ立ち数分布は flags=8 を谷とする二峰型で、9個以上を包括申請とみなして用途別集計から除外します（除外件数はメタ情報に記録）。
- **座標の粒度**: 出発地は市区町村の重心レベルに秘匿化された座標です。これより細かい粒度へ加工しません。
- **時系列の品質**: 飛行日時に不整合があるため、「ファイル＝対象月」を月の信頼単位とします。
- **欠損**: null 安全に処理し、出発地が判別できない行は「（出発地不明）」として集計、地図には表示しません。

### デプロイ

`main` ブランチへの push で `.github/workflows/deploy-pages.yml` が実行され、リポジトリのルートが GitHub Pages として公開されます（Pages のソースは「GitHub Actions」）。
